1. INTRODUCTION
================================================================================

The Civic Issue Reporting System is a full-stack civic-technology platform
designed to bridge the communication gap between citizens and local municipal
authorities. It empowers citizens to report civic issues — such as potholes,
broken streetlights, garbage accumulation, water leakage, and other urban
infrastructure problems — through a streamlined digital interface with photo
evidence, GPS-based geolocation, and real-time complaint tracking.

The platform follows the principle: "See It. Report It. Fix It."

By digitizing the traditionally manual complaint filing process, the system
aims to improve civic service delivery, enhance transparency, and promote
citizen participation in urban governance.


================================================================================
2. PROBLEM STATEMENT
================================================================================

Citizens in urban areas frequently encounter civic issues such as damaged
roads, malfunctioning streetlights, overflowing garbage bins, and water
supply disruptions. The existing methods of reporting these issues — such
as helpline calls, physical visits to municipal offices, or paper-based
complaint forms — are often:

  - Time-consuming and inconvenient
  - Lacking transparency (no tracking or status updates)
  - Difficult to prioritize without photographic evidence
  - Prone to misrouting across departments
  - Lacking accountability for resolution timelines

There is a clear need for a modern, accessible, and intelligent platform
that allows citizens to submit geo-tagged, photo-verified complaints and
track their resolution in real time.


================================================================================
3. OBJECTIVES
================================================================================

  1. Develop a user-friendly web platform for citizens to report civic
     issues with supporting photographic evidence and precise GPS location.

  2. Implement AI-powered image verification using a YOLOv8 object
     detection model to validate and verify submitted complaint images.

  3. Enable real-time complaint tracking with a visual status timeline
     showing each stage from submission to resolution.

  4. Build a multi-role system supporting Citizens, Zonal Officers,
     Field Workers, and Administrators with role-specific dashboards.

  5. Provide automated complaint routing based on category and geographic
     zone to the appropriate municipal department.

  6. Generate unique complaint IDs (CIV-XXXXX format) for easy reference
     and public tracking.

  7. Create a responsive, mobile-first design accessible from any device.

  8. Establish a RESTful API architecture for extensibility and potential
     integration with external government systems.

7. DATABASE DESIGN
================================================================================

The system uses MongoDB, a NoSQL document database. The primary collections
are:

7.1 USERS COLLECTION
---------------------
  {
    _id              : ObjectId (auto-generated)
    name             : String
    email            : String (unique, indexed)
    phone            : String
    password_hash    : String (bcrypt hashed)
    role             : String ("citizen" | "admin" | "zonal_officer" | "worker")
    created_at       : DateTime
  }

7.2 COMPLAINTS COLLECTION
--------------------------
  {
    _id              : ObjectId (auto-generated)
    complaint_id     : Integer (auto-increment, e.g., 10001)
    citizen_id       : ObjectId (reference to users)
    category         : String (pothole, streetlight, garbage, water, etc.)
    description      : String
    latitude         : Float
    longitude        : Float
    address          : String (reverse geocoded)
    priority         : String (low, medium, high, critical)
    status           : String (SUBMITTED, ASSIGNED, IN_PROGRESS,
                               UNDER_REVIEW, RESOLVED, CLOSED)
    image_path       : String (path to uploaded image)
    audio_path       : String (optional, path to uploaded audio)
    ai_verification  : Object {
                         score: Float,
                         detected_objects: Array,
                         confidence: Float,
                         verified: Boolean
                       }
    assigned_to      : ObjectId (reference to worker/department)
    status_history   : Array of status change records
    created_at       : DateTime
    updated_at       : DateTime
  }

7.3 COUNTERS COLLECTION
------------------------
  {
    _id              : String (e.g., "complaint_id")
    sequence_value   : Integer (current auto-increment value)
  }

7.4 DISTRICTS COLLECTION
-------------------------
  {
    _id              : ObjectId
    name             : String
    zone             : String
    boundaries       : Object (geographic boundaries)
  }

8. MODULE DESCRIPTIONS
================================================================================

8.1 AUTHENTICATION MODULE
--------------------------
  - User registration with input validation
  - Secure password hashing using bcrypt (10 rounds)
  - JWT token generation (HS256 algorithm, 24-hour expiry)
  - Token-based session management (stateless)
  - Protected route middleware for API endpoints
  - Role-based access control (citizen, admin, zonal_officer, worker)

  API Endpoints:
    POST   /api/auth/register   - Register a new citizen
    POST   /api/auth/login      - Authenticate and receive JWT token
    GET    /api/auth/me          - Get current authenticated user profile

8.2 COMPLAINT MANAGEMENT MODULE
---------------------------------
  - Multi-step complaint submission wizard:
      Step 1: Select category (Pothole, Streetlight, Garbage, Water, etc.)
      Step 2: Upload photographic evidence (JPG/PNG, max 10MB)
      Step 3: Capture GPS location or select on interactive map
      Step 4: Add description and set priority
      Step 5: Review and submit
  - Auto-generation of unique complaint IDs (CIV-10001 format)
  - Category-based department routing and priority assignment
  - Complaint status lifecycle tracking
  - Filtering and searching complaints by status, category, and date
  - Public complaint tracking by complaint ID (redacted view)
  - Aggregate public statistics dashboard

  API Endpoints:
    POST   /api/complaints                    - Create new complaint (multipart)
    GET    /api/complaints/my                 - Get authenticated user's complaints
    GET    /api/complaints/:id                - Get complaint details
    GET    /api/complaints/track/:complaintId - Public status tracking
    GET    /api/complaints/public-stats       - Public aggregate statistics

8.3 AI VERIFICATION MODULE
----------------------------
  - YOLOv8 (nano variant) object detection model integration
  - Automatic image analysis on complaint submission
  - Object detection for civic issues: potholes, road damage,
    debris, infrastructure defects
  - Verification scoring algorithm:
      * Exact category match:    +80 points
      * Related detection:       +15-20 points
      * High confidence bonus:   +25 points
      * Confidence penalty:      -7.5 points (if below 90%)
      * Irrelevant objects:      -20 points
  - Results stored with complaint record
  - Manual review flagging for low-confidence submissions

  API Endpoint:
    POST   /api/ai/verify-issue   - AI-assisted image analysis

8.4 ADMIN MODULE
-----------------
  - Centralized admin dashboard
  - View all complaints across the system
  - Assign complaints to departments/workers
  - Update complaint status
  - System analytics and reporting
  - User management capabilities
  - Overdue complaint tracking and escalation

  API Router: /api/admin/*

8.5 ZONAL OFFICER MODULE
--------------------------
  - Zone-specific dashboard
  - View and manage complaints within assigned geographic zone
  - Assign field workers to complaints
  - Monitor resolution progress in zone
  - Zone-level analytics

  API Router: /api/zonal/*

8.6 FIELD WORKER MODULE
-------------------------
  - View assigned complaints
  - Update complaint status as work progresses
  - Upload resolution photos/evidence
  - Mark complaints as resolved
  - Mobile-optimized interface

  API Router: /api/worker/*

8.7 NOTIFICATION MODULE
-------------------------
  - In-app notifications for status changes
  - Real-time updates via WebSocket connections
  - Notification history and management

  API Routers:
    /api/notifications/*
    WebSocket endpoint for real-time updates

8.8 LOCATION & MAPPING MODULE
-------------------------------
  - GPS auto-detection using browser Geolocation API
  - Interactive map using Leaflet.js + OpenStreetMap tiles
  - Click-to-select location on map
  - Reverse geocoding via Nominatim API (coordinates to address)
  - No API key required (fully open-source map stack)

12. COMPLAINT STATUS LIFECYCLE
================================================================================

  SUBMITTED  -->  ASSIGNED  -->  IN_PROGRESS  -->  UNDER_REVIEW  -->  RESOLVED  -->  CLOSED

  Stage 1 - SUBMITTED     : Citizen submits a new complaint
  Stage 2 - ASSIGNED      : Admin/system assigns to a department/worker
  Stage 3 - IN_PROGRESS   : Field worker begins resolution work
  Stage 4 - UNDER_REVIEW  : Supervisor quality check
  Stage 5 - RESOLVED      : Issue fixed, resolution evidence uploaded
  Stage 6 - CLOSED        : Citizen reviews and marks as complete

  Each status transition is logged with:
    - Timestamp
    - Changed by (user ID)
    - Previous status
    - New status
    - Optional notes/comments

13. AI-POWERED IMAGE VERIFICATION
================================================================================

The system integrates YOLOv8 (You Only Look Once, version 8) nano model
for real-time object detection on uploaded complaint images.

  Model: yolov8n.pt (YOLOv8 Nano - ~6.5 MB)
  Framework: Ultralytics
  Dependencies: OpenCV (headless), NumPy, Pillow

  Process:
    1. Citizen uploads a photo with the complaint
    2. Image is preprocessed (resized to 640x640, normalized)
    3. YOLOv8 model runs inference (object detection)
    4. Detected objects are extracted with confidence scores
    5. Objects are matched against the selected complaint category
    6. A verification score (0-100%) is computed
    7. Results are stored with the complaint record

  Verification Outcomes:
    - VERIFIED (score >= 70%)      : Image matches complaint category
    - MANUAL REVIEW (score < 70%)  : Image requires human verification

  This AI verification helps:
    - Reduce false or spam complaints
    - Prioritize genuine issues
    - Speed up the review process for administrators

14. SECURITY MEASURES
================================================================================

  1. Password Security
     - Passwords hashed using bcrypt with 10 salt rounds
     - Plain-text passwords never stored in the database

  2. Authentication
     - JWT tokens with HS256 algorithm
     - 24-hour token expiry
     - Token required for all protected endpoints
     - Stateless authentication (no server-side sessions)

  3. Input Validation
     - Pydantic schema validation on all API inputs
     - Frontend form validation before submission
     - File type and size validation for uploads

  4. CORS Protection
     - Restricted to specific allowed origins
     - Credentials support enabled

  5. File Upload Security
     - File type restrictions (JPEG/PNG for images)
     - File size limits (max 10MB)
     - Server-generated filenames to prevent path traversal

  6. Role-Based Access Control
     - Four distinct roles: citizen, admin, zonal_officer, worker
     - Role-protected routes on both frontend and backend
     - Endpoint-level authorization checks

18. SETUP AND INSTALLATION
================================================================================

PREREQUISITES:
  - Node.js 20+ and npm
  - Python 3.11+ and pip
  - MongoDB (local installation or MongoDB Atlas cloud)

STEP 1: Clone the Repository
  git clone <repository-url>
  cd civic-issue-reporting-system

STEP 2: Backend Setup
  cd backend
  python -m venv .venv
  .venv\Scripts\activate          (Windows)
  source .venv/bin/activate       (macOS/Linux)
  pip install -r requirements.txt

  Create .env file:
    MONGODB_URI=mongodb://localhost:27017/civic-issue-reporting
    JWT_SECRET=replace_with_a_long_random_secret
    JWT_EXPIRES_MINUTES=1440

STEP 3: Frontend Setup
  cd frontend/react-app
  npm install

  Create .env.local file:
    VITE_API_URL=http://localhost:5000/api

STEP 4: Start Backend Server
  cd backend
  uvicorn app.main:app --reload --port 5000
  (Server starts at http://localhost:5000)

STEP 5: Start Frontend Dev Server
  cd frontend/react-app
  npm run dev
  (App opens at http://localhost:3000 or http://localhost:5173)

OPTIONAL: Seed Demo Data
  cd backend
  python seed_admin_accounts.py
  python seed_demo_complaints.py

22. TROUBLESHOOTING
================================================================================

  +-------------------------------+------------------------------------------+
  | Issue                         | Solution                                 |
  +-------------------------------+------------------------------------------+
  | MongoDB connection error      | Ensure MongoDB is running locally or     |
  |                               | Atlas URI is correct in .env             |
  | Backend won't start           | Check .env file exists with valid        |
  |                               | MONGODB_URI and JWT_SECRET               |
  | Frontend API errors           | Ensure backend is running on port 5000   |
  | Login fails                   | Confirm account exists and API is running|
  | Map not loading               | Check internet (uses OpenStreetMap tiles) |
  | Image upload fails            | Ensure backend/uploads/ directory exists |
  | CORS errors                   | Check allowed origins in backend config  |
  | YOLO model not loading        | Ensure yolov8n.pt exists in backend/     |
