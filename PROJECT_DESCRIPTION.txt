================================================================================
1. EXECUTIVE SUMMARY & PROJECT VISION
================================================================================

Modern urban centers are strained by deteriorating infrastructure, delayed
repairs, and fragmented municipal communication channels. Conventional civic
complaint portals function as passive digital "inboxes" where tickets sit in
First-Come, First-Served (FIFO) queues regardless of severity, while field
workers are assigned manually without visibility into workload or proximity.

CivicPulse (Civic Issue Reporting System) fundamentally reimagines urban
governance by transforming civic complaint processing into an active,
data-driven Civic Intelligence Platform.

By combining modern full-stack web engineering (React 19, FastAPI, MongoDB)
with edge computer vision (Ultralytics YOLOv8), geospatial indexing (MongoDB
2dsphere), multi-factor priority scoring, automated field-worker load
balancing, and 30-day predictive hotspot forecasting, CivicPulse automates the
entire civic problem-resolution lifecycle:
"See It -> Verify It -> Prioritize It -> Assign It -> Resolve It -> Verify It."

KEY HIGHLIGHTS:
  - 4 Distinct Stakeholder Portals with custom workflows and role guards.
  - 13 Administrative Districts of Delhi mapped with sub-divisions & keywords.
  - 8 Proprietary AI & Computational Engines running synchronously & in background.
  - 67+ Secure REST API Endpoints with JWT authentication & RBAC.
  - Real-Time Duplex WebSockets for instantaneous role-based notifications.
  - Side-by-side Before/After photo proof verification for field repairs.
  - 100% Automated Backend Test Suite (Pytest) and production Vite build.

2. CORE PROBLEM STATEMENT & MUNICIPAL BOTTLENECKS
================================================================================

Urban infrastructure administration suffers from five systemic bottlenecks:

  1. Reporting Friction & Context Loss:
     Citizens struggle with complex municipal bureaucracy. Phone hotlines lose
     exact GPS coordinates, while paper registers lack photo evidence, causing
     technicians to arrive at incorrect sites with inadequate equipment.

  2. Triage Paralysis & FIFO Inefficiency:
     Traditional civic portals queue all complaints uniformly. A decorative
     pothole in an alleyway is treated identically to an open, life-threatening
     manhole on a major arterial corridor outside a hospital.

  3. Duplicate Complaint Flooding:
     When a water main bursts or a sinkhole opens on a high-traffic road, scores
     of citizens file identical complaints. Municipal staff spend hours
     manually deduping tickets instead of deploying field technicians.

  4. Sub-Optimal Worker Allocation & Technician Burnout:
     Field technicians are dispatched manually by paper work-orders without
     real-time knowledge of worker proximity, trade specialization (electrical
     vs. asphalt vs. sanitation), or existing queue depth, causing technician
     overload and severe SLA breaches.

  5. Purely Reactive Maintenance:
     Municipal leadership acts only after citizen outrage or infrastructure
     collapse. Municipalities lack predictive tools to recognize emerging
     recurring failure corridors before catastrophic breakdowns occur.

CivicPulse directly eliminates these bottlenecks through computer vision,
geospatial intelligence, mathematical priority ranking, and automated triage.

6. THE 8 CORE AI & COMPUTATIONAL INTELLIGENCE ENGINES
================================================================================

--------------------------------------------------------------------------------
6.1 ENGINE 1: COMPUTER VISION & DEFECT RECOGNITION (`ai_service.py`)
--------------------------------------------------------------------------------
  - Model: Ultralytics YOLOv8 Nano (`yolov8n.pt`).
  - Architecture: Lightweight, fast inference (<120ms on CPU).
  - Capabilities:
    * Analyzes uploaded complaint photos against 80 COCO classes mapped into
      civic defect categories (potholes, street damage, streetlights, garbage,
      drainage, fire hydrants, public benches).
    * Computes bounding boxes (`x1, y1, x2, y2`) around detected defects.
    * Generates defect verification score (0.0 to 1.0).
    * Anti-Spam Detection: If an uploaded image contains irrelevant objects
      (e.g., animals, food, indoor selfies, pure black/blank images), the issue
      is automatically routed to the Super Admin Suspicious Review Queue.
    * Synthetic Image Testing Fallback: Includes fallback simulation mode for
      headless unit testing without GPU requirements.

--------------------------------------------------------------------------------
6.2 ENGINE 2: MULTI-FACTOR AI PRIORITY ENGINE (`priority_service.py`)
--------------------------------------------------------------------------------
  Calculates a continuous mathematical priority score from 0.0 to 100.0 using
  5 distinct operational dimensions:

  +-------------------------------+--------+----------------------------------+
  | Dimension                     | Weight | Calculation Logic                |
  +-------------------------------+--------+----------------------------------+
  | 1. Inherent Category Severity | 30%    | Water contamination: 0.95 (28.5) |
  |                               |        | Open drainage / manhole: 0.90    |
  |                               |        | Deep road crater/pothole: 0.70   |
  |                               |        | Dark corridor streetlight: 0.65  |
  |                               |        | Structural road damage: 0.60     |
  |                               |        | Garbage accumulation: 0.50       |
  |                               |        | Public property damage: 0.45     |
  | 2. AI Vision Confidence       | 20%    | YOLO model detection confidence  |
  | 3. Geospatial Incident Density| 20%    | 500m radius scan of active issues|
  | 4. Citizen Upvote Momentum    | 15%    | Community verification velocity  |
  | 5. Complaint Aging & SLA Risk | 15%    | Prevents backlog starvation      |
  +-------------------------------+--------+----------------------------------+

  Score-to-Priority Mapping:
    - 80.0 – 100.0 : CRITICAL (12-hour SLA)
    - 60.0 –  79.9 : HIGH     (24-hour SLA)
    - 35.0 –  59.9 : MEDIUM   (48-hour SLA)
    -  0.0 –  34.9 : LOW      (72-hour SLA)

--------------------------------------------------------------------------------
6.3 ENGINE 3: SMART DUPLICATE DETECTION & CLUSTER PREVENTION (`duplicate_service.py`)
--------------------------------------------------------------------------------
  Prevents ticket spamming and duplicate clutter through composite 4-stage matching:
  1. Geospatial Haversine Filter:
     Calculates great-circle distance between coordinates. Only complaints
     within a 200-meter radius are considered candidate duplicates.
  2. Category Equality Check:
     Only issues matching the exact failure category (e.g. pothole to pothole)
     are evaluated.
  3. Token-Based Jaccard Text Similarity:
     Preprocesses citizen descriptions into lowercase normalized word tokens.
     Calculates intersection over union: Jaccard = |A ∩ B| / |A ∪ B|.
  4. 72-Hour Temporal Window:
     Restricts search to unresolved complaints filed within the preceding 72 hours.

  Actionable Frontend Experience:
  When a candidate duplicate is detected during filing, the wizard displays the
  existing ticket's live photo, status, and offers a 1-click "Upvote Existing
  Issue" button. This prevents duplicate tickets while increasing the original
  ticket's priority score through citizen momentum.

--------------------------------------------------------------------------------
6.4 ENGINE 4: DYNAMIC RESOLUTION ETA & CAPACITY ENGINE (`eta_service.py`)
--------------------------------------------------------------------------------
  Computes precise completion target dates instead of static generic strings:
  - Category Base Durations:
    * Water Contamination: 6 hours
    * Hazardous Drainage: 12 hours
    * Streetlight Failure: 24 hours
    * Road Damage / Pothole: 48 hours
    * Garbage Clean-up: 24 hours
  - Priority Speed Multipliers:
    * CRITICAL : 0.50x base duration
    * HIGH     : 0.75x base duration
    * MEDIUM   : 1.00x base duration
    * LOW      : 1.25x base duration
  - District Worker Shortage Penalty:
    Evaluates active worker capacity in the district. If all technicians are
    busy or carrying >3 tasks, the ETA dynamically expands by 25–50% and flags
    `workerShortage = True`, alerting administrators to dispatch reinforcements.

--------------------------------------------------------------------------------
6.5 ENGINE 5: INTELLIGENT FIELD WORKER ASSIGNMENT (`assignment_service.py`)
--------------------------------------------------------------------------------
  Ranks and matches candidate field technicians using a multi-criteria formula:
  - District Proximity Match (30%): Worker assigned to the incident's district.
  - Workload Balance (25%): Workers carrying 0–2 active tasks score highest.
  - Availability Status (20%): `AVAILABLE` = 100%, `BUSY` = 40%, `OFF_DUTY` = 0%.
  - Trade Skill Specialization (15%): Direct match with category trade skills.
  - Historical Performance (10%): Historical on-time completion and star ratings.

  Strict Overload Safeguard:
  Any technician currently holding 5 or more active tasks is strictly marked as
  `OVERLOADED` and disqualified from automatic assignment, preventing worker
  burnout and missed deadlines.

--------------------------------------------------------------------------------
6.6 ENGINE 6: 30-DAY PREDICTIVE CIVIC HOTSPOTS FORECASTER (`prediction_service.py`)
--------------------------------------------------------------------------------
  Transforms municipal operations from reactive fire-fighting into proactive
  preventive infrastructure maintenance:
  - Lookback Window: Analyzes the preceding 30 days of municipal complaints.
  - Split-Half Acceleration Analysis:
    Divides the period into two 15-day chronological halves (Days 1–15 vs.
    Days 16–30) to compute the acceleration rate-of-change:
    Velocity Acceleration = (Count_H2 - Count_H1) / max(Count_H1, 1).
  - Risk Classification:
    * HIGH RISK   : Acceleration > +50% with >= 5 recent incidents.
    * MEDIUM RISK : Acceleration between +15% and +50%.
    * STABLE      : Acceleration < +15%.
  - Actionable Municipal Prescriptions:
    Generates operational advisories (e.g., "High-risk drainage cluster detected
    in East Delhi. Recommend pre-monsoon culvert desilting before heavy rainfall").
  - Small-Sample Statistical Safeguard:
    Gracefully prevents false alarm panics by requiring a minimum statistical
    threshold (at least 5 recorded incidents) before flagging a risk hotspot.

--------------------------------------------------------------------------------
6.7 ENGINE 7: AI EXECUTIVE COMMAND CENTER INSIGHTS (`insights_service.py`)
--------------------------------------------------------------------------------
  Synthesizes city-wide operational health into an automated executive briefing:
  - Executive City Health Index (0–100%):
    Dynamically calculated from overall resolution rate, percentage of tickets
    within SLA, and average citizen satisfaction rating.
  - Operational Risk Flags:
    Flags unassigned tickets idling past 4 hours, districts with rising overdue
    rates, and departments facing severe technician shortages.
  - Prescriptive Directives:
    Produces structured executive recommendations for municipal commissioners.

--------------------------------------------------------------------------------
6.8 ENGINE 8: CONTINUOUS SLA MONITORING & AUTO-ESCALATION (`overdue_service.py`)
--------------------------------------------------------------------------------
  Ensures citizen complaints never fall through administrative cracks:
  - Dynamic SLA Thresholds:
    * CRITICAL : 12 Hours
    * HIGH     : 24 Hours
    * MEDIUM   : 48 Hours
    * LOW      : 72 Hours
  - Continuous SLA Scanning:
    Background service monitors `slaDeadline` timestamps across all active tickets.
  - Automatic Status Escalation:
    When a ticket breaches its deadline, the engine automatically:
    1. Updates `slaStatus = BREACHED`.
    2. Transitions status to `ESCALATED`.
    3. Records an automated audit log entry.
    4. Emits real-time WebSocket emergency alerts to Zonal and Super Admins.
  - Manual Scan Trigger:
    Super Admins can execute an on-demand scan anytime via `/api/admin/escalate/scan`.

7. FORMAL STATE MACHINE & COMPLAINT LIFECYCLE
================================================================================

Every complaint transitions through a strictly governed lifecycle state machine
implemented in `backend/app/models/complaint.py` and `status_service.py`:

                     [ SUBMITTED ]
                           |
            +--------------+--------------+
            |                             |
      (Standard Triage)          (AI Flagged Suspicious)
            |                             |
            v                             v
       [ ASSIGNED ]               [ UNDER_REVIEW ]
            |                             |
      (Worker Accepts)             +------+------+
            |                      |             |
            v                  (Verified)    (Dismissed)
     [ IN_PROGRESS ]               |             |
            |                 [ ASSIGNED ]  [ REJECTED ]
    (Worker Submits Proof)
            |
            v
  [ RESOLUTION_SUBMITTED ]
            |
      +-----+-----+
      |           |
  (Approved)  (Rework Required)
      |           |
      v           +------------------> [ IN_PROGRESS ]
  [ RESOLVED ]
      |
 (Citizen Rates / Admin Signs Off)
      |
      v
  [ VERIFIED ]
      |
      v
   [ CLOSED ]  (Terminal State)

SPECIAL STATE TRANSITIONS:
  - [ ANY ACTIVE STATE ] ----(Breached SLA)----> [ ESCALATED ]
  - [ ESCALATED ] ---------(Reassigned)--------> [ ASSIGNED ] / [ IN_PROGRESS ]
  - [ RESOLVED ] ----------(Unresolved/Reopen)-> [ REOPENED ] -> [ ASSIGNED ]
  - [ REJECTED ] ----------(Super Admin Override)--> [ SUBMITTED ]

     Passwords hashed using Passlib with salted bcrypt (cost factor 12).
  2. Stateless JWT Authentication:
     Tokens signed via HMAC-SHA256 with 24-hour expiration (`JWT_EXPIRES_MINUTES=1440`).
  3. Role-Based Access Control (RBAC):
     FastAPI dependency injection (`require_super_admin`, `require_zonal_admin`,
     `require_worker`, `get_current_user`) strictly protects every endpoint.
  4. Client-Side Route Protection:
     React `ProtectedRoute` and `RoleProtectedRoute` prevent unauthorized URL navigation.
  5. Image EXIF GPS Spoofing Detection:
     Extracts hardware EXIF GPS coordinates from uploaded photos and cross-checks
     against user-reported browser coordinates. Mismatches >500m are flagged.
  6. Rate Limiting:
     Maximum 5 submissions per hour per IP/user to prevent denial-of-service spam.
  7. AI Computer Vision Anti-Spam:
     YOLOv8 automatically detects irrelevant images (food, animals, indoor selfies)
     and shunts them to the Super Admin Suspicious Review Queue.
  8. Worker Overload Safeguard:
     Technicians holding >= 5 active tasks are disqualified from automatic dispatch.
  9. Immutable Audit Trail:
     All status overrides, user bans, and credential updates are permanently recorded
     in `audit_logs` with actor ID, timestamp, and metadata payload.
 10. Forced Credential Rotation:
     Newly provisioned workers and admins receive `is_temporary_password = True`,
     requiring a forced password change upon first login.

  - Python (v3.11 or v3.13) and pip
  - MongoDB 7+ running locally (`mongodb://localhost:27017`) or MongoDB Atlas

--------------------------------------------------------------------------------
STEP 1: BACKEND CONFIGURATION & INITIALIZATION
--------------------------------------------------------------------------------
  1. Open a terminal in the `backend` directory:
     cd backend

  2. Create and activate a Python virtual environment:
     python -m venv .venv
     # Windows:
     .venv\Scripts\activate
     # Linux / macOS:
     source .venv/bin/activate

  3. Install backend dependencies:
     pip install -r requirements.txt

  4. Configure environment variables in `backend/.env`:
     MONGODB_URI=mongodb://localhost:27017/civic-issue-reporting
     JWT_SECRET=super_secret_civicpulse_jwt_key_2026
     JWT_ALGORITHM=HS256
     JWT_EXPIRES_MINUTES=1440

  5. Populate Database with Default Admin & Worker Accounts:
     python seed_admin_accounts.py

  6. Populate Database with Realistic Seed Complaints:
     python seed_demo_complaints.py

  7. Launch the FastAPI Backend Server:
     python -m uvicorn app.main:app --port 5000 --reload
     * API Root    : http://localhost:5000
     * Swagger UI  : http://localhost:5000/docs
     * ReDoc       : http://localhost:5000/redoc

--------------------------------------------------------------------------------
STEP 2: FRONTEND CONFIGURATION & INITIALIZATION
--------------------------------------------------------------------------------
  1. Open a separate terminal in `frontend/react-app`:
     cd frontend/react-app

  2. Install frontend dependencies:
     npm install

  3. Launch the Vite Development Server:
     npm run dev
     * Web Application: http://localhost:5173 (or http://localhost:3000)
